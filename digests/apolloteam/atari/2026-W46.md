### Atari core 13000 testing: big benchmark gains, SD card and SoundDMA bugs
blast666 tested cores 12856 and 13000 on V4SA; with ol4865's new NVDI driver and MINT080.PRG, memory and video benchmarks improved sharply, though SD card and SoundDMA problems remain.

- Core 12856 lost the mouse pointer until NVDI.PRG was renamed to NVDI.PRX; no sprite in that core.
- Core 13000 restores network via v4net_ata.xif but the SD card is not visible; OS shows errors opening files.
- MxPlay loops the start of an mp3; its author says Buffptr() returns bogus values, so the DMA address counter is wrong.

### biggun68080 explains core clock base and roadmap: 080 MAC, 128-bit memory, 3 ALU
After blast666 compared cores of different clocks, biggun68080 said default is 8MHz base x11 (88MHz) and focus is stability, Falcon compatibility and enabling DSP/MAC and 128-bit memory.

- Filenames will get a multiplier; default base is 8MHz and multiplier x11.
- Arne added eMAC-style instructions to 080, usable on all 32 data registers and memory; faster MP3 decoding expected.
- Planned: 128-bit memory controller, 3 ALU, two dcache reads per cycle, 128-bit AMMX; up to 120MHz considered.

### MiNT memory protection can't be enabled on 68060-style core
MiNT Setter shows memory protection off even when selected at boot; ol4865 suspects MiNT relies on ROM-provided MMU setup that EmuTOS lacks on 68060, and asked Mikro.

- Memory protection can only be changed during MiNT boot (Shift, then 5), not in MiNT Setter.

❓ **Open:** Who sets up the MMU on this core remains undecided.
