## Top topics

### Upcoming AMMX 128 release: faster MOVE16 and masked sprite instructions
biggun68080 announced a release with AMMX 128 within days, aimed at boosting 2D games, with a 3D update planned for later.

- MOVE16 now takes 2 cycles; new `move16.mb` (byte mask) and `move16.mw` (word mask) push 16 bytes with sprite write checks.
- On 8-bit screens one instruction copies 16 sprite pixels; rogue_particle uses 16x16 and 32x32 sprites with 0 as transparent.
- biggun68080 says 128-bit AMMX exists to remove bottlenecks and that memory bandwidth is very strong; 3D update expected in about 2 months.

❓ **Open:** rogue_particle asked whether documentation exists for the new instructions; no answer given.

### PIP on V4: advised against as unstable, undocumented on purpose

### opForge assembler reaches near feature parity on AmigaOS 68020
eriktier reports the native 68020 AmigaOS opForge now has near full feature parity and supports many CPU families including 68080 with AMMX.

- CPU support loads from bytecode files such as `68080.opn`, so adding a CPU mostly means adding a file.
- opForge is self-hosting; eriktier is migrating projects to it on an A6000 and expects to upgrade 68080 support.
